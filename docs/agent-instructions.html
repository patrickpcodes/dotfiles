01

The idea

Each agent looks for its global instructions in its own place. Those places become links (dashed arrows) that lead back into the repo. Claude takes one extra step: its CLAUDE.md imports a fixed path, and that path is also a link.

Loading...
Why Claude imports ~/.config/agents/AGENTS.md. The repo is at F:\Repositories\dotfiles on Windows and ~/dotfiles on Enterprise. The import uses a path that's the same on every machine, and the installer points it at whichever clone is local.
A link is a pointer, not a copy. Opening ~/.codex/AGENTS.md opens the repo file. Deleting a link never deletes its target. If the target is missing (for example, F: isn't mounted), the agent simply finds no file.

The one rule that changed in the shared file

### When Starting Work
- 1. **Read Context**: Always start by reading AGENTS.md and README.md
+ 1. **Read Context**: Always start by reading README.md. Follow the repo's AGENTS.md too;
+    where it conflicts with these global instructions, the repo's rules win.

Everything else is your opencode-config working copy, unchanged apart from line endings (now LF). It never mentions OpenCode, so nothing else needed neutral wording.

Why there are no symlinks committed to Git

Stow links each file in a package to exactly one place. Getting one file to show up at three paths with Stow alone means committing symlinks into the repo, and Git for Windows usually checks those out as small text files containing a path (core.symlinks=false). So the shared file is stored once in agents/. Stow handles the two packages that fit its layout (agents, claude), and the installers link the Codex and OpenCode paths straight to the shared file.

Why --no-folding: without it, Stow could turn the whole ~/.config/agents folder into a link into the repo, and anything a tool wrote there would land in your repo.

Verify on Enterprise

Guarantees

  • Safe to rerun: the second run makes 0 changes.
  • A real file is always renamed with a timestamp, never deleted.
  • A correct link is left alone.
  • Never touches ~/.claude/settings.json or ~/.codex/config.toml.
  • Respects CODEX_HOME and XDG_CONFIG_HOME if they're set.

Extra checks in install.sh

  • Stops if a parent folder leads into the repo (a folded stow link), so it never writes into your clone.
  • A dry run works without stow and only warns. A real run requires stow.
  • shellcheck: no findings.

08

Adding rules

Every agent

Edit agents/.config/agents/AGENTS.md and keep the wording tool-neutral. Commit and push, then pull on the other machines. The links pick it up with no reinstall.

Claude Code only

Add rules to claude/.claude/CLAUDE.md below the import line. They're in the repo, so they reach every machine.

Codex only

Codex reads exactly one global file and has no imports. AGENTS.override.md replaces the shared file rather than adding to it. Instead, use developer_instructions in ~/.codex/config.toml, which adds to it. That file is local to each machine and not managed by dotfiles.

OpenCode only

List extra files under instructions in opencode.json. OpenCode adds them to AGENTS.md. It doesn't follow @ imports.
